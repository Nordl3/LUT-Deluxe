# Ultimate Studio four-voice DDS bank format — release 2.0.0

This describes the new export generated by **Export Studio → Four-Voice Teensy ZIP**, not the unchanged V1.04 firmware input. `BANK_FORMAT.md` describes the older Classic Lab 1.3 bank format.

- All sample data is unsigned **uint16 little-endian**, regardless of the 12-bit or future 16-bit DAC profile.
- Four independent bank binary files (`.bin`) each hold samples in layout **[band][morph frame][sample]**, with `samples` entries per frame. Use the JSON manifest to read sizes and identify voices.
- Band 0 is unfiltered. Optional bands 1–9 are FFT-limited for pitch ceilings 40, 80, 160, 320, 640, 1280, 2560, 5120 and 10240 Hz respectively, at a 48 kHz design rate. These upper-frequency band entries are defined in the manifest and generated C++ header. Do not use pitch ceilings above playback Nyquist; the final band cannot preserve rich timbres at extreme high pitches.
- DAC samples represent `round((wave+1)/2 * DAC_MAX)`. `DAC_MAX` is 3090, 4095 or 65535. No illegal 4096 value is generated for the MCP4822.
- The `.h` contains four named `static const uint16_t [LUT_BANDS][LUT_FRAMES][LUT_SAMPLES]` arrays and morph correction arrays. Generated identifiers start with a sanitized project name and channel index to prevent collisions between user-defined voice names.
- A `.morph.f32` file accompanies each channel. It stores little-endian IEEE 32-bit floating-point **[transition][position][gain,offset]**, with `frameCount-1` transitions and **17 positions (16 intervals)** per transition. For a fractional position within a transition, interpolate gain and offset, then calculate `corrected = sample * gain + offset` on a signed normalized float sample, *before* quantizing to DAC code. The correction is measured from the full-resolution base bank. Pitch-filtered tables may require a different normalization policy, so do not blindly apply base correction to all filtered bands.
- The manifest also includes each channel's editable role, family, frequency `ratio`, `phase` normalized to 0–1 cycle, `octave`, `semitones`, `detune` in cents, mix level and stereo position. They are **metadata for future DDS firmware**; not automatically applied to the sample table itself.
- For best results, store `ratio` and octave as multipliers of the shared CV-derived root frequency. As a separate hardware consideration, verify ADC CV span and scaling before claiming precise 1V/oct tracking.
- All wavetable and mixer synthesis is separate from the current analogue hardware; external VCAs and filters are not implemented by these data files.

## Flash planning

Raw sample bytes (before the much larger C++ text representation) are approximately `4 * bands * frames * samples * 2`; morph correction arrays contribute additional data. An 8-frame × 256-sample × four-channel bank with one band occupies 16 KiB raw sample data, while 32 × 512 × four channels with one band uses 128 KiB. Ten pitch bands multiply sample storage by ten. The real usable flash is less than physical installed flash because the firmware also occupies space.
